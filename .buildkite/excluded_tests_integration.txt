# Aiven patch 066 — refreshable-MV coordination replica name is shard-qualified.
# ----------------------------------------------------------------------------
# In a Replicated database the MV-refresh coordination znode is SHARED across all
# shards (it is keyed by {uuid}, not {shard}). Patch 066 makes the coordination
# replica identity globally unique by qualifying it with the shard name, so
# `system.view_refreshes.last_refresh_replica` reports `<shard>/<replica>` (e.g.
# `shard1/1`) instead of the bare `<replica>` (`1`) — see
# src/Storages/MaterializedView/RefreshTask.cpp (the "066:" comment near
# `coordination.replica_name = coordination.shard_name + "/" + ...`).
# The three upstream cases below assert on the bare name and so fail with e.g.
# `assert 'shard1/1' == '1'` even though the refresh itself succeeds (correct
# rows, last_success_time != 0, no exception). Intended golden shift, not a
# regression. The other 10 cases in this module pass and stay enabled, so this is
# scoped to the affected node IDs rather than the whole file.
test_refreshable_mv/test.py::test_refreshable_mv_in_replicated_db
